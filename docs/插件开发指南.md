# bit_pouch 插件开发指南

> 目标：读完能独立新增一个工具，且不需要改路由、首页或构建配置。
>
> 先读 [`API接入文档.md`](API接入文档.md) 了解 manifest / run / ToolResult 的统一契约；本文讲内置插件的落地步骤。

## 1. 最快路径

```bash
npm run plugin:new -- timestamp "时间戳转换" "Timestamp Converter" convert
```

生成：

```text
src/plugins/timestamp/
  manifest.ts
  run.ts
  View.vue
  run.spec.js
  README.md
```

然后：

```bash
npm run check:plugins
npm test
npm run dev
```

打开 `http://localhost:5173`，工具已经出现在首页。

## 2. 目录契约

| 文件 | 必需 | 作用 |
|------|------|------|
| `manifest.ts` | 是 | 纯数据清单：id、名称、描述、分类、图标、关键词、运行时、平台、排序 |
| `run.ts` | 是 | 纯函数计算入口，导出 `run` |
| `View.vue` | 是 | 工具界面 |
| `run.spec.js` | 建议 | 行为测试；迁移工具必须保留 ihomy 基线测试 |
| `README.md` | 建议 | 协议细节、边界、已知限制 |

目录名必须等于 `manifest.id`，且匹配 `^[a-z][a-z0-9-]*$`。

## 3. 清单

```ts
import type { ToolManifest } from '@/core/types'

export default {
  id: 'timestamp',
  name: { zh: '时间戳转换', en: 'Timestamp Converter' },
  description: { zh: 'Unix 时间戳与本地时间互转', en: 'Convert Unix timestamps and local time' },
  category: 'convert',
  icon: 'clock',
  keywords: ['timestamp', 'unix', 'time', '时间戳', '时间'],
  version: '0.1.0',
  runtime: 'main',
  platforms: ['web', 'desktop', 'mobile'],
  offline: true,
  order: 60,
} satisfies ToolManifest
```

| 字段 | 规则 |
|------|------|
| `id` | 与目录名一致；kebab-case |
| `name` / `description` | 必须同时有 `zh` 与 `en` |
| `category` | `codec` / `convert` / `inspect` / `network` / `text` |
| `icon` | 在 `src/components/ToolIcon.vue` 登记；未登记回退 `wrench` |
| `keywords` | 中英文都放，搜索会匹配 |
| `runtime` | `main` 或 `worker`；>50ms/大输入用 worker |
| `platforms` | 非空子集 `web` / `desktop` / `mobile` |
| `offline` | 默认 `true`；有网络必须显式评审 |
| `order` | 数字小的在前；缺省 100 |
| `experimental` | 可选，界面上显示 Beta 标记 |

**不要**在 `manifest.ts` 里 import 视图、运行时代码或依赖 DOM 的模块。清单会被同步收集用于首页列表。

## 4. run 契约

```ts
import type { ToolRun } from '@/core/types'

export interface TimestampRunData {
  seconds: number
  iso: string
}

export const run: ToolRun<TimestampRunData> = (input, options, ctx) => {
  if (!input.trim()) {
    return { ok: false, error: { code: 'empty', message: ctx.locale === 'zh' ? '请输入内容' : 'Input is empty' } }
  }
  // 纯计算……
  return {
    ok: true,
    output: resultText,
    stats: { chars: resultText.length },
    data: { seconds, iso },
  }
}
```

### 4.1 返回值

```ts
interface ToolResult<T> {
  ok: boolean
  output?: string
  error?: {
    code: string
    message: string        // 已按 ctx.locale 本地化
    line?: number
    column?: number
    char?: string
    lineText?: string
  }
  stats?: Record<string, number | string>
  data?: T
}
```

- `output`：用户可直接复制的文本。
- `data`：结构化结果，供视图渲染表格/卡片。
- `stats`：底部统计条的标量。
- 业务错误**不要抛异常**；返回 `ok:false`。Runner 只处理基础设施异常。

### 4.2 硬性约束

1. **纯函数**：不访问 DOM、`window`、`document`、`localStorage`、网络、时间以外的全局可变状态。
2. **不修改入参**：把 `input`/`options` 当只读。
3. **确定性**：相同输入 + 选项 → 相同输出（时间戳“当前时间”这类工具把 now 作为显式选项传入）。
4. **Worker 安全**：`runtime: 'worker'` 时返回值必须可结构化克隆；不要返回 `Uint8Array`、类实例、函数。用 `number[]` 替代字节数组。
5. **本地化**：错误文案按 `ctx.locale` 返回，不要在视图里维护第二套错误字典。
6. **上限**：对超大输入设置明确上限并返回可读错误，避免卡死。

## 5. Worker 插件

把 manifest 的 `runtime` 改为 `'worker'` 即可，视图仍调用 `callTool`，无需改代码。

Runner 会：

- 懒加载 `run.ts` 到单例 Worker；
- 30s 超时后销毁重建；
- Worker 不可用时回退主线程；
- 插件自身抛错原样返回，不回退。

注意事项：

- Worker 内不能访问 DOM，也不能假设 `window` 存在。
- 大字符串会被复制；10MB 级输入要评估内存峰值。
- 单 Worker 同一时刻只跑一个计算；视图应做请求序号守卫，避免旧结果覆盖新结果。

## 6. View 契约

```vue
<script setup lang="ts">
import { ref } from 'vue'
import Pane from '@/components/Pane.vue'
import CopyButton from '@/components/CopyButton.vue'
import { locale, t } from '@/core/i18n'
import { callTool } from '@/core/runner'
import { useToolPrefs } from '@/core/toolPrefs'
import type { TimestampRunData } from './run'

const prefs = useToolPrefs('timestamp', { unit: 'seconds' as 'seconds' | 'millis' })
const input = ref('')
const output = ref('')
let seq = 0

async function runNow(): Promise<void> {
  const current = ++seq
  const result = await callTool<TimestampRunData>('timestamp', input.value, { unit: prefs.unit }, locale.value)
  if (current !== seq) return
  output.value = result.ok ? (result.output ?? '') : ''
}
</script>
```

### 6.1 共享组件

| 组件 | 用途 |
|------|------|
| `Pane` | 带标题/操作区/底栏的面板 |
| `CopyButton` | 复制并提示，内置 WebView 回退 |
| `SegmentedControl` | 分段选择 |
| `StatChips` | 统计标签 |
| `ErrorNote` | 统一错误展示（码/行列/行文本） |
| `ToolCard` / `EmptyState` | 首页与空态 |

### 6.2 Core API

| API | 用途 |
|-----|------|
| `callTool(id, input, options, locale, signal?)` | 统一执行入口 |
| `useToolPrefs(id, defaults)` | 只持久化选项 |
| `copyText(text)` | 复制 + toast |
| `t(key)` / `localized(text)` / `locale` | 国际化 |
| `pushToast(message, tone)` | 轻量提示 |
| `formatBytes` / `formatInt` | 数字格式 |

### 6.3 视图职责

- 防抖：编码 120ms、报文 180ms、进制 60ms、子网 90ms；JSON 显式运行。
- 竞态：用递增序号丢弃旧结果。
- 渲染上限：表格/高亮设上限，超出显示截断提示。
- 空态/错误态：不要白屏。
- 可访问性：输入有 label，图标按钮有 aria-label。

## 7. 测试

```js
import { describe, it, expect } from 'vitest'
import { run } from './run'

describe('timestamp', () => {
  it('rejects empty input', () => {
    expect(run('', {}, { locale: 'zh' }).error?.code).toBe('empty')
  })
})
```

要求：

- 正常路径、边界（空/上限/极端值）、错误码。
- 迁移工具保留 ihomy 原 spec，函数名与错误码对齐。
- 纯函数测试不要挂载 Vue 组件；视图交互用手工用例覆盖（见 `test/cases/功能测试用例.md`）。

## 8. 评审清单

- [ ] 目录名 = manifest.id；清单双语完整。
- [ ] `run.ts` 无 DOM/存储/网络访问。
- [ ] 输入不写入任何持久化。
- [ ] 错误返回 `ok:false` 且有本地化 message。
- [ ] 有 `run.spec.js`，边界覆盖。
- [ ] 大输入有上限或 Worker。
- [ ] 视图有防抖、竞态守卫、空/错误态。
- [ ] 新增依赖已评估体积/离线/跨端，并记录。
- [ ] 已同步 ihomy 在线工具页（`bitPouchTools.js` + 面板 + `tools.<id>` 中英文案 + 计数），或在变更归档说明不迁移原因。
- [ ] `npm run check:plugins && npm test && npm run typecheck && npm run build` 通过。

### 8.1 在线工具页同步

ihomy 的 `/bit-pouch/tools` 是同一批工具的在线入口。两仓不共享运行时代码，在线侧按下列步骤独立实现：

1. **登记目录**：在 ihomy `frontend/src/tools/bitPouchTools.js` 追加 `{ id, no, titleKey, descKey, keywords }`，`no` 接续现有编号；`id` 必须与 bit_pouch 插件目录名一致，同一能力不要拆成多个入口，数量以 `npm run check:plugins` 为准。
2. **登记面板**：在 `frontend/src/views/bitpouch/BitPouchTool.vue` 的 `PANELS` 中用 `defineAsyncComponent` 映射到新面板，保证目录页不加载工具代码。合并或改名工具时，在 ihomy 路由里为旧 `/bit-pouch/tools/<旧id>` 加重定向。
3. **写面板**：在 `frontend/src/views/bitpouch/panels/` 新建 `<Name>Panel.vue`，复用 `BpcChips` / `BpcCopy` 与 `bpc-*` 类；模板里所有可见文案走 `$t`，不要硬编码中文。
4. **移植逻辑**：在 `frontend/src/utils/tools/` 新建纯 JS 模块，行为、输出与错误码对齐 bit_pouch 的 `run.ts`；两仓各自维护测试，不在 ihomy 运行期引用 bit_pouch 源码。
5. **补文案**：`frontend/src/i18n/zh-CN.js` 与 `en.js` 同时新增 `tools.<id>.*`，并更新发布页/目录的工具计数、简介与 kicker。
6. **处理依赖**：在线侧若需要 bit_pouch 用到的解析器，加入 `frontend/package.json`；用动态 `import()` 保持面板独立 chunk。
7. **验证**：`npx vitest run` 覆盖 i18n 四道闸门与新工具 spec，改动文件 ESLint 0 error，`npm run build` 通过；浏览器打开目录与各面板跑一次示例。

确实无法在线复现（依赖文件系统、本地二进制等）的，在 `docs/变更归档.md` 写明原因，并保留本地工具。

## 9. 用户插件（运行时）

内置插件需要改代码并重新构建；用户插件不需要。在自己常用的编辑器里写好单文件 JavaScript，再从设置页「用户插件」导入；安装后立即注册进工具列表，和内置工具共用首页、搜索、命令面板与 `/t/:id` 路由。

### 9.1 代码格式

代码被当作**函数体**执行（严格模式），最后 `return { manifest, run }`；也兼容 `export default { ... }`。不支持 `import`，插件必须自包含。

```js
return {
  manifest: {
    id: 'my-upper',
    name: { zh: '我的大写工具', en: 'My uppercase tool' },
    description: { zh: '把输入转成大写', en: 'Uppercase the input' },
    category: 'text',
    icon: 'text',
    keywords: ['upper'],
    version: '0.1.0',
  },
  run(input, options, ctx) {
    return { ok: true, output: input.toUpperCase(), stats: { chars: input.length } }
  },
}
```

清单必填：`id`、`name.zh/en`、`description.zh/en`、`category`。其余字段有默认值：`icon: 'wrench'`、`keywords: []`、`version: '0.1.0'`、`runtime: 'main'`、`platforms` 三端、`offline: true`、`order: 100`。

### 9.2 执行与返回值

- 用户插件固定跑在主线程，不进入 Worker；`run` 可以同步返回，也可以返回 Promise。
- 可以直接返回字符串，或返回标准 `ToolResult`。
- 返回值由 `normalizeToolResult` 收敛：`output` 转成字符串，`stats` 只保留 number/string，`data` 原样保留；格式不对返回 `PLUGIN_RESULT`。
- 业务错误建议返回 `{ ok: false, error: { code, message } }`；抛出的异常由 runner 收敛成 `PLUGIN_ERROR`。

### 9.3 限制与存储

| 项 | 规则 |
|----|------|
| 单个插件源码 | ≤ 64KB |
| 插件数量 | ≤ 32 |
| id | kebab-case；不能与内置工具冲突；相同 id 再次安装视为更新 |
| 持久化 | `bitpouch:user-plugins:v1`（localStorage），只存插件源码与安装时间 |
| 网络 | 不做任何上传或自动下载 |

### 9.4 安全模型

用户插件和页面同权限运行：可以访问 DOM、`localStorage`、`fetch`，也可以阻塞主线程。**只安装你信任的代码**。它面向“用户自己写、自己用”的本地扩展，不是沙箱，也不是插件市场；对外分发前必须另行设计签名、权限与隔离（Worker / iframe）。

### 9.5 管理

设置页只负责：导入 `.js` / `.mjs` 文件、下载示例、导出已安装插件、删除。**不提供内置编辑器**，插件在用户自己的编辑器里编写；相同 id 再次导入视为更新。坏插件不会阻止应用启动，会在「加载失败的插件」中列出，可直接删除。

### 9.6 与内置插件怎么选

- 长期维护、需要 Worker、自定义视图或完整测试 → `src/plugins/` 内置插件。
- 一次性转换、个人小工具、想立即试用 → 用户插件。

## 10. 常见问题

**首页没有出现新工具？** 重启 dev server；确认目录在 `src/plugins/` 下且 `manifest.ts` 默认导出对象。

**构建报清单校验失败？** 看 `npm run check:plugins` 的具体行；常见是 id 与目录名不一致、缺 `en` 文案、category 拼错。

**Worker 里报 `document is not defined`？** run.ts 访问了 DOM；把计算与渲染分开。

**结果里有 `Uint8Array`，Worker 返回后变成空对象？** 结构化克隆不能保留类型；转成 `number[]`。

**输入内容出现在 localStorage？** 检查是否把整个 `state` 传给了 `useToolPrefs`；只传选项字段。
