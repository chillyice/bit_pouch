# bit_pouch 文档索引

> 一页地图：每份文档一句话定位 + 谁该读。新成员/新会话从这里出发，不必通读全部。

## 推荐阅读顺序

1. 根 `README.md` —— 项目是什么、怎么跑起来（3 分钟）
2. `docs/架构设计.md` —— 插件模型、执行模型、性能与跨端策略（20 分钟）
3. `AGENTS.md` —— 项目规则与硬性约定；AI 会话自动加载
4. `docs/插件开发指南.md` —— 动手加第一个工具前必读
5. `docs/踩坑速查.md` —— 改代码/排查异常前按关键词检索
6. `docs/需求设计说明书.md` —— 只读你负责的工具章节与验收口径
7. `docs/变更归档.md` —— 查历史实现与决策（按时间追加，不要通读）

## 文档维护规矩

- **变更归档**：每次可交付迭代在 `docs/变更归档.md` 末尾追加 `#####` 小节，写文件级改动表、决策、验证结果、必要的数据迁移。不要在 `AGENTS.md` 里写时间线。
- **踩坑**：写 `docs/踩坑速查.md` 对应小节，按“症状 → 真因 → 对策”组织；`AGENTS.md` 最多留一句结论或指针。
- **需求**：功能变化**就地改写** `docs/需求设计说明书.md` 对应章节，让它等于当前事实；不写“本版新增”，不写修订历史。
- **插件契约**：`ToolManifest` / `ToolResult` / Worker 协议变化时，同时更新 `docs/架构设计.md`、`docs/插件开发指南.md`、`AGENTS.md`。
- **数字口径**：工具数量以 `npm run check:plugins` 输出为准；性能数字以一次真实构建为准，并在变更归档记录环境与命令。
- 新增/删除文档时同步更新本索引。
