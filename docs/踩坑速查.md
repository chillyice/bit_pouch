# bit_pouch 踩坑速查

> 格式：**症状 → 真因 → 对策**。先按关键词 grep，再动手。新增条目请附取证命令。

## 1. 工具链

### 1.1 `check-plugins.mjs` 导入 `.ts` 失败

**症状**：`Unknown file extension ".ts"` 或 `Cannot find module '@/core/types'`。

**真因**：

- Node < 22.18 不支持原生 TS 类型剥离。
- `manifest.ts` 里用了**值导入**（`import { X } from '@/core/types'`），Node 会尝试解析别名。类型导入 `import type` 会被剥离，不受影响。

**对策**：

- 使用 Node 22.18+ / 24（本项目开发环境为 Node 24）。
- `manifest.ts` 只写 `import type`；需要运行时校验函数时从 `src/core/manifest.ts` 导入，它同样只依赖类型。
- 老 Node 环境改用 `tsx` 或 esbuild 预处理。

**取证**：

```bash
node -e "import('./src/plugins/json/manifest.ts').then(m=>console.log(m.default.id))"
```

### 1.2 Vite Worker 里 `import.meta.glob` 路径找不到

**症状**：Worker 运行时报“插件 xx 缺少 run.ts”或 `NOT_FOUND`。

**真因**：glob 路径是**相对当前文件**的。`src/core/worker/tool.worker.ts` 到插件目录是 `../../plugins/*/run.ts`；`src/core/registry.ts` 到插件目录是 `../plugins/*/run.ts`。写错一层就收集不到。

**对策**：保持 registry/worker 的 glob 前缀与文件位置一致；用 `npm run check:plugins` 与浏览器 Network 面板确认插件 chunk 是否生成。

### 1.3 Windows / OneDrive 构建冲突

**症状**：`npm run build` 偶发 `EBUSY`、`EPERM`，或 `dist/` 文件被同步占用。

**真因**：OneDrive 实时同步 + 杀毒软件扫描构建产物；并行构建会争同一目录。

**对策**：

- 不要在 OneDrive 同步进行中并行跑多个 `npm run build`。
- `dist/`、`dev-dist/`、`src-tauri/target/` 已加入 `.gitignore`，但 OneDrive 仍会同步；必要时暂停同步或把构建目录指向本地临时盘。
- 失败后先关掉 dev server / 文件预览再重试，不要反复 `rm -rf`。

### 1.3.1 dev server 监听 Rust 构建产物后崩溃

**症状**：`npm run dev` 运行中突然退出，日志末尾是 `Error: EBUSY: resource busy or locked, watch '...\src-tauri\target\debug\build\...exe'`（Node `FSWatcher` 抛出，进程直接死）。

**真因**：Vite/chokidar 默认监听整个项目根，包含 `src-tauri/target`；cargo 编译出的 `.exe` 被 cargo 或 OneDrive 占用，watch 调用失败且异常未被捕获。跑完 `cargo check` / `cargo build` 后最容易复现；`vite.config.ts` 变更触发 server 重启重建 watcher 时必然踩中。

**对策**：

- `vite.config.ts` 的 `server.watch.ignored` 必须包含 `**/src-tauri/target/**`（`dist/`、`dev-dist/` 同理），已配置，勿删。
- 新增顶层产物目录时同步补进 ignored。
- 崩溃后直接重新 `npm run dev` 即可，无残留状态。

**取证**：崩溃日志搜 `EBUSY` + `src-tauri`；确认 `vite.config.ts` 中 ignored 列表存在。

### 1.4 含中文文件被 PowerShell 写坏

**症状**：中文变 `?` 或乱码；文件头多出 BOM。

**真因**：PowerShell 5.1 默认编码不是 UTF-8；`Set-Content`/`WriteAllText` 会按 ANSI 处理。

**对策**：含中文的源码/文档一律用 Read/Write/Edit 工具；必须用 PowerShell 时显式 `-Encoding utf8`，`.ps1` 带 UTF-8 BOM。

### 1.5 CRLF/LF 抖动

**症状**：`git diff` 整文件全红，或脚本按 `\n` 切分失败。

**真因**：Windows 编辑器写 CRLF，仓库 `text=auto`；部分脚本按 LF 处理。

**对策**：`.gitattributes` 已统一源码为 CRLF、Rust 为 LF；批量改写文档用二进制读写并保持 `\r\n`，小改用 Edit。

## 2. 插件系统

### 2.1 首页工具列表为空 / 清单校验启动失败

**症状**：白屏，控制台 `插件清单校验失败`。

**真因**：`manifest.ts` 不是默认导出、id 与目录名不一致、缺 `en` 文案、category 拼错、`platforms` 为空。

**对策**：

```bash
npm run check:plugins
```

按输出逐条修。`main.ts` 的 `assertRegistry()` 是故意的硬失败，避免半残列表。

### 2.2 首页加载变慢 / 所有工具代码进了入口

**症状**：入口 chunk 突然变大，首页 Network 里出现所有插件视图。

**真因**：在 `manifest.ts` 里 import 了 `View.vue`、`run.ts` 或重型依赖；或 `registry.ts` 把 `runLoaders` 写成了 `eager: true`。

**对策**：清单只放纯数据；run/View 保持懒加载；用 `npm run build` 的输出核对 chunk。

### 2.3 Worker 返回 `{}` 或丢字段

**症状**：主线程拿到的 `data` 为空、`Uint8Array` 变普通对象、函数丢失。

**真因**：结构化克隆不支持类实例/函数/部分宿主对象；`Uint8Array` 虽然可克隆，但跨线程后类型/内容处理容易出错。

**对策**：run 返回普通对象；字节数组转 `number[]`；在 spec 里直接调 run 验证返回形状。

### 2.4 Worker 超时后所有请求都失败

**症状**：一次大输入超时后，后续小输入也报错。

**真因**：超时路径销毁了 Worker，但旧请求的 pending 记录没有全部清理；或新请求复用了已终止的实例。

**对策**：`runner.ts` 的 `rejectAll()` 必须在 terminate 前后都执行；超时后把 `worker` 置空，下次 `ensureWorker()` 重建。修改后用大 JSON 连续触发两次超时验证。

### 2.5 输入卡顿 / 旧结果覆盖新结果

**症状**：快速输入时结果闪烁，显示上一次的内容。

**真因**：异步 run 返回顺序不保证；视图没有序号守卫。

**对策**：视图用 `const seq = ++runSeq`，返回后 `if (seq !== runSeq) return`。参考 JSON/编码/进制/报文/子网视图。

## 3. JSON

### 3.1 长整数末尾变 0

**症状**：`12345678901234567890` 格式化后变成 `12345678901234567000`。

**真因**：用了 `JSON.parse` + `JSON.stringify`，数字被转成双精度。

**对策**：保留自写 token 解析器，数字与字符串都用原始字面量输出。不要为了“简化”改回 `JSON.parse`。

### 3.2 重复键消失

**症状**：`{"k":1,"k":2}` 格式化后只剩一个 `k`。

**真因**：同上，JS 对象键唯一。

**对策**：解析器用 `entries` 数组保存键值对，不构建 JS 对象。

### 3.3 大 JSON 渲染卡死

**症状**：格式化 1MB JSON 后页面冻结。

**真因**：逐 token 生成几万个 `<span>`，主线程布局爆炸。

**对策**：输出超过 200,000 字符关闭高亮；输入上限与 Worker 超时兜底；不要用 `v-html` 拼接。

### 3.4 错误行列不直观

**症状**：只报“解析失败”，用户不知道哪一行。

**真因**：异常只带 code/index，没有换算行列。

**对策**：`describeError` 把 index 换算为 line/column 并截取当前行文本；视图用 `ErrorNote` 展示。

## 4. 字符编码

### 4.1 Emoji 变成两个乱码字符

**症状**：`😀` 编码/解码后变成两个代理对字符。

**真因**：按 UTF-16 code unit 遍历，没有用 `for...of` / `codePointAt`。

**对策**：编码用 `for (const ch of text)`；非 BMP 输出 `\uD83D\uDE00`；解码用 `String.fromCodePoint`。

### 4.2 Base64 大文本报参数上限

**症状**：`String.fromCharCode(...bytes)` 抛 `Maximum call stack size exceeded`。

**真因**：展开运算符一次传太多参数。

**对策**：按 0x8000 分块拼接；`fromBase64` 先忽略空白并补齐 `=`。

### 4.3 URL 解码抛异常

**症状**：用户输入 `%E4%BD` 时页面报未捕获错误。

**真因**：`decodeURIComponent` 对不完整序列抛 `URIError`。

**对策**：捕获并返回 `invalidUrl`；视图展示 ErrorNote。

## 5. 进制转换

### 5.1 大整数精度丢失

**真因**：`parseInt` / `Number` 超过 2^53。

**对策**：整数用 BigInt；`toBaseString` 用 BigInt 取模；不要混用 Number。

### 5.2 `0b` 在 16 进制里被误删

**症状**：16 进制输入 `0b10` 被当成二进制前缀。

**真因**：无条件剥离 `0x/0b/0o`。

**对策**：只在进制匹配时剥离（16↔0x、2↔0b、8↔0o）。

### 5.3 小数显示一长串

**症状**：`0.1` 转二进制出现几十位。

**对策**：最多 16 位，除不尽标记 `≈`，去掉末尾 0；这是有意的近似表达。

## 6. 报文解析

### 6.1 奇数位十六进制

**症状**：`AAB` 解析成两个字节或报错不明确。

**对策**：显式返回 `oddHex`；不要自动补 0，避免用户误判。

### 6.2 CRC16 对不上

**症状**：Modbus 帧 CRC 与设备不一致。

**真因**：多项式/初值/反射方向不同。本项目用 CRC16/MODBUS：初值 `0xFFFF`，多项式 `0xA001`（反射），低字节在前。

**验收**：`01 03 00 00 00 0A C5 CD` 整包结果为 `0000`，除末尾 2 字节为 `CDC5`。

### 6.3 字段表越界

**症状**：模板声明长度大于报文，页面报错或读到脏数据。

**对策**：`splitFields` 按可用字节截断并标记 `truncated`；偏移始终基于实际消费的字节数。

## 7. 子网计算

### 7.1 网络地址变成负数

**症状**：`192.168.1.0` 计算后出现 `-64` 之类。

**真因**：JS 位运算默认 32 位有符号。

**对策**：所有位运算结果 `>>> 0`；输出用 `ipToString` 逐字节取。

### 7.2 非连续掩码被当成合法

**症状**：`255.0.255.0` 算出一个奇怪前缀。

**对策**：`maskToPrefix` 校验 `prefixToMask(prefix) === mask`，否则返回 `maskNonContiguous`。

### 7.3 `/31` `/32` 主机数为负

**真因**：统一用 `total - 2`。

**对策**：`/31` 两个地址都可用；`/32` 单机可用；只有 `/0–/30` 扣网络与广播。

## 8. Tauri

### 8.1 `tauri build` 报缺少图标

**症状**：`icon.ico` / `icon.icns` not found。

**对策**：

```bash
npm run tauri icon src-tauri/app-icon.svg
```

生成 `src-tauri/icons/` 后重新构建。图标文件入库。

### 8.2 桌面白屏

**症状**：窗口打开但空白；DevTools 显示资源 404。

**真因**：路由用了 web history 且静态协议不支持 rewrite；或 `frontendDist` 路径错。

**对策**：本项目用 hash history；确认 `frontendDist: "../dist"` 且 `npm run build` 产物存在。

### 8.3 全局快捷键不生效

**真因**：

- 插件未注册或权限缺失。
- 快捷键被系统/其他应用占用。
- 移动端编译了桌面专属代码。

**对策**：确认 `tauri-plugin-global-shortcut` 已在 `Cargo.toml`；注册在 `#[cfg(desktop)]` 内；换一个组合键做对照测试。

### 8.4 Windows 上 `cargo check` 失败

**症状**：找不到 `link.exe` / Windows SDK。

**真因**：只装了 Rust，没有 MSVC Build Tools 或 WebView2。

**对策**：安装 Visual Studio Build Tools（C++ 桌面开发）与 WebView2 Runtime；`rustup show` 确认默认 toolchain 是 `stable-x86_64-pc-windows-msvc`。

## 9. PWA

### 9.1 安装图标不显示

**真因**：manifest 里只给了 PNG 路径但文件不存在，或 SVG 图标未被浏览器接受。

**对策**：`public/` 已提供 `icon-180.png`、`icon-192.png`、`icon-512.png`、`icon-maskable-512.png`；改图标后重新生成并核对 manifest 路径。maskable 必须满幅不透明，不能用普通圆角图代替。

### 9.3 `tauri icon -p` 不生成默认平台图标

**症状**：执行 `tauri icon ... -p 192,512` 后，`icons/` 下的 ico/icns/128 等没有更新。

**真因**：设置 `-p` 时 CLI 只输出指定尺寸，默认全套图标被跳过。

**对策**：分两次运行——先不带 `-p` 生成平台全套，再带 `-p` 和 `-o public` 生成 PWA 尺寸；maskable 用满幅源图单独生成后改名。

### 9.2 更新后仍是旧版本

**真因**：Service Worker 预缓存了旧 bundle。

**对策**：`registerType: 'autoUpdate'`；必要时刷新一次或清除站点数据。发版后确认页脚版本号。

## 10. UI / 交互

### 10.1 移动端底部导航遮挡内容

**对策**：`page` / `tool-page` 底部 padding 使用 `calc(86px + env(safe-area-inset-bottom))`；不要用固定 `padding-bottom: 20px`。

### 10.2 深色/浅色切换后图表颜色不对

**真因**：组件内硬编码了色值。

**对策**：全部改用 CSS 变量；新增颜色先加到 `src/styles/app.css` 的 token 区。

### 10.3 `color-mix` 在旧 WebView 不生效

**症状**：移动端顶栏背景透明。

**对策**：`color-mix` 只用于增强；提供纯色/半透明 `background` 作为回退。发布前在目标 Android WebView 验证。

### 10.4 自动化点击工具卡片超时（Playwright / 浏览器测试）

**症状**：`getByRole("heading"/"link")` 定位到首页工具卡片后 `click()` 一直等待 actionability 超时；用 `evaluate(el => el.click())` 却能成功。

**真因**：`.tool-card` 有 `rise` 入场动画（opacity 0→1），点击时元素仍处于动画中，Playwright 判定“不稳定”而持续等待。HMR 重渲染会重启动画，放大该现象。

**对策**：

- 卡片已加 `data-tool-id` 属性，测试用 `locator('[data-tool-id="json"]')` 定位。
- 自动化脚本要么等动画结束（>600ms），要么直接 `evaluate` 派发 click。
- 若觉得动画影响真实体验可去掉，但不要为此删 `data-tool-id`（它同时服务于无障碍测试定位）。

### 10.5 ZCode 内置浏览器截图失败

**症状**：`browser screenshot activity capture failed for guest`；随后 `tabs.get` 可能报 webview not ready。

**真因**：IAB 截图能力在部分会话不可用（环境限制），与项目代码无关。

**对策**：布局验证改用 `domSnapshot()`；需要视觉证据时用真实 Chrome 打开 dev server 手工截图。

### 10.6 IAB 后台标签的 Transition 动画卡住

**症状**：命令面板打开后 `.cmd-overlay` 一直带 `cmd-enter-from cmd-enter-active`、`opacity: 0`；Playwright 点击结果项超时，但 Vue 的 `paletteOpen` 状态可能已经变化。

**真因**：IAB 标签不在前台时 `requestAnimationFrame` 被节流/暂停，Vue Transition 的入场/离场类不会推进；不是应用逻辑错误。

**对策**：

- 逻辑验证直接读 DOM 状态或 Vue `setupState`，不要以动画中的可见性判断成败。
- 键盘输入用 `evaluate` 向目标 input 派发 `keydown`，避免 IAB `press` 因焦点/动画失败。
- 需要真实视觉验证时，把标签切到前台或等待动画帧恢复。
