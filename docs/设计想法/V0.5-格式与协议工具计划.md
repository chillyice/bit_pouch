## 1. 共同约定

每个新工具固定生成：

```text
src/plugins/<id>/
  manifest.ts     # 纯数据清单
  run.ts          # 纯函数入口，导出 run
  View.vue        # 界面
  run.spec.js     # 行为测试
  README.md       # 能力、边界、错误码、已知限制
```

统一要求：

- 目录名必须等于 `manifest.id`，匹配 `^[a-z][a-z0-9-]*$`。
- `name` / `description` 必须同时有 `zh` 与 `en`。
- `offline: true`；不发起任何网络请求。
- `run.ts` 不访问 DOM / `window` / `localStorage` / 网络；不修改入参。
- Worker 插件返回值必须可结构化克隆；字节用 `number[]`，不要 `Uint8Array`。
- 错误统一返回 `{ ok:false, error:{ code, message } }`，`message` 按 `ctx.locale` 本地化；不要向视图抛裸异常。
- 输入只参与当前计算。**Cookie、Authorization、cURL 里的 token 一律不写入 localStorage、日志或任何远端。**
- 选项可以持久化，输入不可以；视图用 `useToolPrefs`。
- 视图复用 `Pane`、`CopyButton`、`SegmentedControl`、`StatChips`、`ErrorNote`；支持 `Ctrl+Enter` 运行、复制输出、移动端单列、输入 Tab 不跳出。

新增工具不需要改 router、首页或构建配置；`import.meta.glob` 会自动发现。

### 2.1 清单

```ts

name: { zh: '数据格式转换', en: 'Data Format Converter' }
description: {
  zh: 'YAML / TOML / INI / .env / Properties 与 JSON 互转',
  en: 'Convert between YAML, TOML, INI, .env, Properties and JSON',
}
category: 'convert'
icon: 'braces'
keywords: ['yaml', 'toml', 'ini', 'env', 'properties', 'json', 'convert', '配置', '转换']
version: '0.1.0'
runtime: 'worker'
platforms: ['web', 'desktop', 'mobile']
offline: true
order: 35
```

### 2.2 依赖

- `yaml`（YAML 1.2 解析/序列化）。
- `smol-toml`（TOML 解析/序列化）。
- INI / .env / Properties 手写，不引依赖。

安装前先看体积与许可证：

```bash
npm view yaml version license
npm view smol-toml version license
npm install yaml smol-toml
```

默认静态引入；如果构建后单个工具 chunk 超过预算（gzip 30KB），改为在 `run.ts` 内按格式动态 `import()`，把依赖留在独立 chunk。最终数字写进 `docs/变更归档.md`。

### 2.3 选项

```ts
interface DataFormatOptions {
  mode: 'toJson' | 'fromJson'   // 默认 toJson
  format: 'auto' | 'yaml' | 'toml' | 'ini' | 'env' | 'properties' | 'json'
  target: 'json' | 'yaml' | 'toml' | 'ini' | 'env' | 'properties'  // fromJson 时使用
  indent: '2' | '4' | 'tab'      // 默认 2
  flatten: boolean               // 默认 true；INI/env/properties 嵌套对象转点号键
  sortKeys: boolean              // 默认 false
}
```

- `toJson`：读取 `format`，输出 JSON 文本；`format=auto` 时自动识别。
- `fromJson`：读取 JSON，按 `target` 输出。
- 自动识别优先级：输入以 `{` / `[` 开头 → JSON；含 `[section]` 且行内有 `=` → TOML 或 INI（看是否出现 `"""`、数组表 `[[...]]`、引号键）；含 `---` 或 `key:` → YAML；`KEY=value` 且键全大写 → .env；`key=value` 且含 `\uXXXX` 转义 → properties。无法判断时返回 `unsupportedFormat`，提示手动选择，不要猜错后静默输出。

### 2.4 数据形状

```ts
interface DataFormatData {
  sourceFormat: 'json' | 'yaml' | 'toml' | 'ini' | 'env' | 'properties'
  targetFormat: 'json' | 'yaml' | 'toml' | 'ini' | 'env' | 'properties'
  keyCount: number
  warnings: string[]   // 本地化后的提示
}
```

`output` 是转换后的文本；`data` 供视图显示统计和警告。

### 2.5 行为与边界

**通用**

- 输入上限 1,000,000 字符；嵌套上限 100 层。
- 拒绝 `__proto__`、`constructor`、`prototype` 作为键，返回 `unsafeKey`。
- 解析后统一用普通对象/数组/字符串/数字/布尔/null；不要返回 `Map`、`Date`、类实例。
- 注释在解析后丢弃；源文本含注释时给 `commentsDropped` 警告。

**YAML**

- 使用 `parseDocument` + `toJS({ maxAliasCount: 100 })`；超过别名上限返回 `tooManyAliases`。
- 多文档（`---` 分隔多个）返回 `multiDocument`，本版不做数组输出。
- 锚点/别名展开后如果有环，返回 `cyclicReference`。
- 日期按字符串保留；不要自动转 `Date`。

**TOML**

- 解析后把日期/时间值归一化为 ISO 字符串。
- 数组表、内联表正常转成数组/对象。
- 浮点 `nan` / `inf` 在 JSON 输出时转成字符串 `"nan"` / `"inf"`，并给警告 `nonFiniteNumber`。

**INI**

- 支持 `;` / `#` 注释、节 `[name]`、`key=value` / `key:value`。
- 输出扁平对象：节内键写成 `section.key`，全局键保持原名；重名时后者覆盖并给 `duplicateKey` 警告。
- JSON → INI：`flatten=true` 时递归展开嵌套对象；数组和非标量返回 `nestedNotSupported`。`flatten=false` 时顶层对象即节，第二层必须是标量对象。

**Properties**

- 支持 `\uXXXX`、`\n`、`\t`、反斜杠续行、`=` / `:` 分隔。
- 输出扁平点号键；值中的特殊字符按 Properties 规则转义。

**env**

- 支持 `export KEY=value`、单双引号、`#` 注释。
- JSON → env：只允许扁平标量对象；键必须匹配 `^[A-Za-z_][A-Za-z0-9_]*$`，否则 `invalidKey`；值含换行或特殊字符时加双引号并转义。
- 嵌套对象/数组返回 `nestedNotSupported`。

**JSON**

- `toJson` 的 `json` 格式等价于校验 + 美化；`fromJson` 的 `target=json` 等价于重排/排序。
- 使用内置 `JSON.parse`；检测到超过 `Number.MAX_SAFE_INTEGER` 的整数字面量时给 `precisionLoss` 警告（不阻断）。

### 2.6 错误码

`empty`、`tooLarge`、`tooDeep`、`syntaxError`（带 `line` / `column` / `lineText`）、`unsupportedFormat`、`multiDocument`、`tooManyAliases`、`cyclicReference`、`unsafeKey`、`duplicateKey`、`nestedNotSupported`、`invalidKey`。

`nonFiniteNumber`、`commentsDropped`、`precisionLoss` 只作为 `warnings`，不阻断转换。

### 3.3 解析输入与数据结构

解析模式接受原始文本；允许以空行开头，自动跳过。

```ts
interface HeaderEntry { name: string; value: string; rawName: string }

interface HttpMessageData {
  kind: 'request' | 'response'
  request?: { method: string; target: string; version: string }
  response?: { version: string; status: number; reason: string }
  headers: HeaderEntry[]
  cookies: Array<{ name: string; value: string; attributes: Record<string, string> }>
  query: Array<{ key: string; value: string }>
  body: {
    raw: string
    bytes: number
    encoding: 'utf8' | 'binary' | 'empty'
    contentType: string
    json?: unknown
    form?: Array<{ key: string; value: string }>
    multipart?: Array<{
      name: string
      filename?: string
      contentType?: string
      bytes: number
      preview: string
    }>
    chunks?: Array<{ size: number; bytes: number }>
  }
  warnings: string[]
}
```

`output` 输出该结构的格式化 JSON，方便整体复制；视图主要读 `data`。

### 3.4 解析规则

1. 统一换行扫描：`\r\n` 与 `\n` 都接受；混合换行给 `mixedLineEndings` 警告。
2. 头/体分隔：第一个空行。没有空行时整个输入按头部处理。
3. 起始行：
   - 请求：`METHOD target HTTP/x.y`；`METHOD` 校验 token；`target` 可为 origin-form（`/a?b=1`）或 absolute-form。
   - 响应：`HTTP/x.y STATUS reason`；状态 3 位数字。
   - `HTTP/2` 明文前言、`HTTP/3` 文本返回 `unsupportedVersion`。
   - 无法识别返回 `invalidStartLine`，带行号。
4. 头：
   - 名称必须匹配 token；冒号后去掉 OWS；值保留内部空白。
   - 重复头保留多条；同名 `Set-Cookie` 不合并。
   - obs-fold（以空格/Tab 开头的续行）拼接到上一条，并给 `obsoleteLineFolding` 警告。
   - 头数量上限 500。
5. 正文：
   - `Transfer-Encoding: chunked`：解析十六进制块大小、扩展、块数据、结尾 `0` 与 trailer；块大小非法返回 `invalidChunk`；未结束返回 `truncatedBody`。
   - 有 `Content-Length`：把正文按 UTF-8 编码成字节，按字节数截取再解码；不足返回 `truncatedBody`。
   - 同时有 `Transfer-Encoding` 与 `Content-Length` 时以 chunked 为准并给 `conflictingLength` 警告。
   - 两者都没有但有正文：按剩余全部内容读取，给 `lengthMissing` 警告。
   - `Content-Encoding: gzip/br/deflate`：不解压，标为 `binary`，正文给出十六进制预览，并给 `contentEncodingNotDecoded` 警告。
6. `Content-Type`：
   - `application/json` / `+json`：尝试 `JSON.parse`，失败给 `invalidJsonBody` 警告，不阻断。
   - `application/x-www-form-urlencoded`：解析为 `form`。
   - `multipart/form-data; boundary=...`：按 boundary 切分，解析每部分头，输出 `name`、`filename`、`contentType`、字节数、UTF-8 文本预览（最多 2KB）。分片头非法给 `invalidMultipart` 警告。
7. Query：从请求 target 中取 `?` 之后的内容，保留重复键与原始顺序；格式错误的百分号编码按原文保留并给警告。
8. Cookie：解析 `Cookie` 请求头为键值；`Set-Cookie` 解析 `Path` / `Domain` / `Expires` / `Max-Age` / `Secure` / `HttpOnly` / `SameSite`，属性名统一小写。
9. 二进制正文：UTF-8 解码出现替换字符 `\uFFFD` 时标为 `binary`，给 `binaryBody` 警告，并用十六进制预览代替 `raw`。

### 3.5 生成模式

输入为 JSON 描述；不接受任意文本。示例：

```json
{
  "kind": "request",
  "method": "POST",
  "target": "/api/login?next=%2Fhome",
  "version": "HTTP/1.1",
  "headers": [["Host", "example.com"], ["Content-Type", "application/json"]],
  "body": "{\"name\":\"demo\"}",
  "chunked": false
}
```

响应：

```json
{
  "kind": "response",
  "version": "HTTP/1.1",
  "status": 200,
  "reason": "OK",
  "headers": [["Content-Type", "application/json"]],
  "body": "{\"ok\":true}"
}
```

规则：

- 头名称/值不得含 CR/LF，否则 `invalidHeader`，防止响应拆分。
- `autoContentLength=true` 且有正文且未 chunked 且未显式设置 `Content-Length` 时，按 UTF-8 字节数自动补。
- `chunked=true` 时输出单个块 + 结束块 `0`；去掉 `Content-Length`。
- 请求必须有 `method` 与 `target`；响应必须有 3 位 `status`。
- 输出使用选项指定的换行；头和正文之间保留一个空行。

### 3.6 错误码

`empty`、`tooLarge`、`invalidStartLine`、`unsupportedVersion`、`invalidHeader`、`tooManyHeaders`、`invalidContentLength`、`truncatedBody`、`invalidChunk`、`unsupportedTransferEncoding`、`invalidBuildInput`。

## 4. WP3：`curl-convert` cURL 转换

### 4.1 清单

```ts
id: 'curl-convert'
name: { zh: 'cURL 转换', en: 'cURL Converter' }
description: {
  zh: '把 cURL 命令转换为 fetch / axios / Python / Go / PowerShell 代码',
  en: 'Convert a cURL command into fetch, axios, Python, Go or PowerShell code',
}
category: 'convert'
icon: 'terminal'
keywords: ['curl', 'fetch', 'axios', 'python', 'go', 'powershell', 'http', '请求', '转换']
version: '0.1.0'
runtime: 'main'
platforms: ['web', 'desktop', 'mobile']
offline: true
order: 56
```

本版只做 **cURL → 代码**。反向（fetch/axios → cURL）放到后续迭代，避免用正则解析多语言代码。

### 4.2 选项

```ts
interface CurlConvertOptions {
  target: 'fetch' | 'axios' | 'python' | 'go' | 'powershell'  // 默认 fetch
}
```

### 4.3 解析

输入是 shell 命令行文本，不是要执行的脚本。解析器只做词法切分，不执行任何命令。

词法与续行：

- 行尾 `\` + 换行合并为一行；支持 CRLF。
- 单引号内全部原样；双引号内处理 `\"`、`\\`、`\$`、`` \` ``、`\n`、`\t`；`$'...'` 支持 `\n`、`\t`、`\r`、`\\`、`\'`、`\xHH`、`\uHHHH`。
- 引号外反斜杠转义下一个字符。
- 未闭合引号返回 `unterminatedQuote`，带位置。
- `$VAR` 不做展开，保留字面量并给 `unexpandedVariable` 警告。

命令与 URL：

- 第一个 token 必须是 `curl` 或 `curl.exe`，否则 `notCurl`。
- URL 取第一个非选项 token 或 `--url` 的值；多个 URL 只取第一个并给 `multipleUrls` 警告。
- 没有 URL 返回 `invalidUrl`；只接受 `http://` / `https://`，其他协议给 `unsupportedScheme` 警告但仍生成。

支持的选项（必须覆盖）：

| 类别 | 选项 |
|------|------|
| 方法 | `-X` / `--request` |
| 头 | `-H` / `--header` |
| 正文 | `-d` / `--data` / `--data-raw` / `--data-binary` / `--data-urlencode` |
| 表单 | `-F` / `--form` |
| 查询 | `-G` / `--get` |
| 认证 | `-u` / `--user` |
| Cookie | `-b` / `--cookie`（文件形式给 `cookieFileUnsupported` 警告） |
| 浏览器模拟 | `-A` / `--user-agent`、`-e` / `--referer`、`--compressed` |
| 连接 | `-k` / `--insecure`、`-L` / `--location`、`--max-redirs`、`--connect-timeout` |
| 代理/证书 | `--proxy`、`--cert`、`--key`（生成代码时给 `unsupportedOption` 警告） |
| 静默/输出 | `-s` / `--silent`、`-v` / `--verbose`、`-i` / `--include`、`-o` / `--output`（忽略并给提示） |

规则：

- `-d` 多个值按 cURL 行为用 `&` 拼接；`--data-urlencode name=value` 对 value 做 URL 编码。
- `-F name=value` 为普通字段；`name=@path` 为文件字段；`name=<path` 为文件内容字段。生成代码时文件字段给出明确注释或占位路径。
- `-H "Name: value"` 按第一个冒号切分；没有冒号返回 `invalidHeader`。
- `-G` 把 `-d` 数据拼到 URL 查询串，方法默认 GET。
- 有 `-d` / `-F` 且没有 `-X` 时，方法默认 POST。
- 短选项簇支持 `-sS`、`-kL`；带值短选项支持 `-XPOST`、`-H'...'`。
- 未知选项不猜测其是否带值：记入 `warnings`，继续解析；如果最终找不到 URL，返回 `invalidUrl` 并提示可能是未知选项导致。
- 输入上限 100,000 字符。

数据结构：

```ts
interface CurlRequest {
  method: string
  url: string
  headers: Array<[string, string]>
  body?: string
  form?: Array<{ name: string; value?: string; file?: string; contentType?: string }>
  auth?: { user: string; password: string }
  insecure: boolean
  followRedirects: boolean
  compressed: boolean
  cookies?: string
}

interface CurlConvertData {
  request: CurlRequest
  warnings: string[]
}
```

### 4.4 代码生成

每个目标都要有稳定、可读、可复制的输出；不要输出 `TODO` 占位而不说明。

- **fetch**：`await fetch(url, { method, headers, body, redirect: 'follow' })`；GET/HEAD 不输出 `body`；`insecure` 给警告（浏览器不能关闭 TLS 校验）。
- **axios**：`axios.request({ method, url, headers, data })`；有 basic auth 时用 `auth: { username, password }`；`insecure` 用注释说明 Node `httpsAgent`。
- **python**：`import requests` + `requests.request("POST", url, headers=..., data=..., auth=(...), verify=False)`；JSON 正文保留原始字符串，不自动 `json=`，避免改写用户数据。
- **go**：生成可编译片段：`http.NewRequest`、逐条 `req.Header.Set`、`strings.NewReader`、`http.Client`；`insecure` 时给出 `tls.Config{InsecureSkipVerify: true}` 并注释风险；补 import。
- **powershell**：`Invoke-WebRequest -Uri ... -Method ... -Headers @{...} -Body '...'`；`insecure` 使用 `-SkipCertificateCheck`（注明仅 PowerShell 7+）。

转义规则：

- JS / JSON：`JSON.stringify`。
- Python：单双引号择一，处理反斜杠与换行。
- Go：`strconv.Quote` 风格转义。
- PowerShell：单引号字符串，内部 `'` 双写。
- 多行正文在 fetch/axios/python 中用模板字符串或三引号，保持可读。

### 4.5 错误码

`empty`、`notCurl`、`unterminatedQuote`、`missingValue`、`invalidUrl`、`invalidHeader`、`tooLong`。

## 10. 风险与默认决策

1. **多会话冲突**：当前 `format` 合并在途。开工前必须确认归属；不要 stash、不要 `git add -A`。若原会话仍在改同一文件，等它完成或另开分支。
2. **依赖预算**：`yaml` + `smol-toml` 可能让 `data-format` chunk 超 80KB。默认静态引入，超预算改动态加载；不因此放弃功能。
3. **YAML 安全**：禁用自定义类型/代码执行；限制别名数量；拒绝原型污染键。不要把 `yaml` 的 `eval` 类能力引入。
4. **HTTP 文本与字节**：粘贴进来的是字符串，Content-Length 按 UTF-8 重新编码计算；二进制正文只能给十六进制预览，不承诺还原原始字节。
5. **cURL 解析边界**：不执行 shell 展开；`$VAR`、命令替换、进程替换不解析，给警告。未知选项可能影响 URL 识别，必须让警告可见。
6. **敏感数据**：HTTP 报文、Cookie、Authorization、cURL token 只存在当前组件内存；不写入 prefs、localStorage、日志。
7. **在线目录漂移**：以本地 id 为准；合并 `format` 后同步在线条目；`markdown` 的本地缺失单独记录，不在本批静默忽略。
8. **不做实时网络**：本批所有工具都是离线纯函数；WebSocket 实时调试、HTTP 客户端另立项目。
